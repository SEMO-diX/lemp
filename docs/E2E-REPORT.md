# Fresh Repository / Fresh Chat E2E Report

Date: 2026-10-01 (Asia/Tokyo)

## Purpose

Prove the public LEMP v1.1 reference flow end to end using a fresh GitHub memory repository and fresh ChatGPT conversations, while keeping validated canonical memory isolated from newer unvalidated state.

The test used only synthetic memory generated by the public `lemp init` template.

## Test repositories

- Public runtime: `SEMO-diX/lemp`
- Fresh private memory repository: `SEMO-diX/lemp-e2e-memory`

The private E2E repository contains only synthetic demonstration data.

## Environment

- Android Termux
- Python 3.14.6
- Git 2.55.0
- Public runtime installed from immutable Git SHA
- GitHub access for the E2E repository was restricted with a repository-scoped fine-grained token

The public project CI separately covers Python 3.11 and 3.12.

## Canonical Gate bootstrap defect discovered by E2E

The first push exposed a real defect in the generated first-checkpoint Canonical Gate shell script.

Observed evidence:

- E2E Canonical Gate Run #1
- run id: `36741044936`
- result: `failure`
- failing step: `Validate checkpoint sequence`
- shell error: unexpected end of file

The defect was fixed in public PR #2 by replacing the malformed bootstrap heredoc, closing the shell conditional correctly, and adding a regression test that runs `bash -n` against the generated checkpoint-sequence script.

Public fix commit:

```text
738d35931fc6f11fa9eeee68809253233f715fe8
```

The fix passed Public LEMP CI on Python 3.11 and 3.12.

## Unvalidated candidate isolation

A newer unvalidated commit was then created deliberately:

```text
candidate SHA:
8f89dc89528b52fcfaaed4d6f21508ed1e61b19a
```

The candidate added a synthetic marker to `STATE.md` that does not exist in the canonical snapshot.

The candidate was then made the new `main` HEAD without advancing the memory checkpoint. As expected:

- Canonical Gate Run #3
- run id: `36744944240`
- result: `failure`
- failing step: `Validate checkpoint sequence`
- promote job: `skipped`
- canonical tag remained `lemp-valid/CP000001`
- canonical commit remained `eb031c3fd96e395c357109ae9cbd575cc917b8dc`

Authoritative local status reported:

```text
canonical sha: eb031c3fd96e395c357109ae9cbd575cc917b8dc
candidate sha: 8f89dc89528b52fcfaaed4d6f21508ed1e61b19a
candidate relation: NEWER_UNVALIDATED
integrity: PASS
attestation_scope: remote-workflow-verified
```

A direct check of `lemp sync` output confirmed that the candidate-only marker was absent from canonical working context.

A second fresh ChatGPT conversation independently recovered the canonical durable state and reported the newer candidate as one commit ahead of canonical, while keeping candidate content out of durable state reconstruction.

During that fresh-chat run, the assistant reported that it had initially inspected top-level `main` structure before re-reading and validating the pinned canonical snapshot. That structural inspection did not affect durable authority: the final recovered state was sourced only from the validated canonical commit.
